# 収益設計の見直し（2026-08-25）

利用者からの問い：**「このサイトはアフィリエイト専用にしようとしている？ どんなサイトなら稼げるのか。
今の構成はあまり良くない気がする」**

この文書は、その問いに repo の記録と外部調査で答えたもの。
**`検証済み` と `未検証` を区別する。** 試算は仮定を明示する。

---

## 1. このサイトはアフィリエイト専用か → **はい。設計上そうなっている**

`検証済み`（リポジトリの実装）

| 根拠 | 場所 |
|---|---|
| Amazonアソシエイトの開示文言とPR表記を持っている | `site/content/site.json` の `affiliateDisclosure` / `prLabel` |
| 本文に `[[LINK:商品名]]` の差し込み位置がある（**55箇所**。ただし `2l-tateru` だけ0箇所） | `site/content/articles/*.md` |
| 審査に合格したら `affiliateEnabled: true` にする設計 | `site/README.md` |
| 記事10本・180日3件の適格販売という審査条件を前提に運営している | `docs/affiliate-program-facts.md` |

**＝ 商品比較でAmazonアソシエイト収益を得る前提の専用サイト。** 迷いなくそう作られている。

## 2. いまの構成の弱点は4つ

### ★ 弱点A｜**測定がまだ1回も動いていない**（いちばん重い）

`検証済み` — `affiliateEnabled: false` なので**リンクが1本も出力されていない。**
55箇所すべてが `link-todo` のプレースホルダ。
⚠️ **記事02（`2l-tateru`）だけリンク位置が0箇所。** 書いた当時に入れ忘れている。

`serp-check.md` は自分でこう決めていた：

> **リンククリック率と購入率（仮定2・3）が、結論を丸ごと動かす。**
> → これは自分の記事で実測するしかない。**最初の数記事は「収益を出す」より
> 「クリック率と購入率を測る」ことが目的になる。**

**その測定が始まらないまま、記事だけが7本に増えた。**
`harness-core.md` の「当てるのではなく測る」に照らして、**いま最も外れている点。**

⚠️ ただし `affiliate-program-facts.md` の第0-2節で確認したとおり、
**申請とリンク掲載は記事が揃う前でも可能で、180日のタイマーは申請時点から動く。**
→ **「いつ申請するか」は利害が対立する判断であり、利用者に投げるべき事項。**

### ★ 弱点B｜**収益記事（キラーページ）が1本も無い**

`未検証`（一般論・出典は下記）— アフィリエイトサイトの一般的な設計は
**収益記事1割：集客記事9割**で、集客記事から収益記事へ内部リンクを集める形。

出典：[ConoHa ワプ活「アフィリエイト記事の書き方」](https://www.conoha.jp/lets-wp/affiliate-kiji-kakikata/)／
[Joujilog「成果の出る内部リンクの貼り方」](https://joujilog.com/internal-linking-for-earning-in-blog-affiliate/)

**このサイトの7記事は、すべて集客記事にあたる。**

| 記事 | 型 | 読者が最後に得るもの |
|---|---|---|
| 500ml何本 / 2L立つか / 保冷剤 / 容量L / ダイワvsシマノ / 内寸の長さ / 土鍋 | **調べ物の答え** | **数値** |

**「で、どれを買えばいいのか」に答える記事が無い。**
関連記事リンクは効いている（同カテゴリ優先に修正済み）が、行き先も全部集客記事なので、
**回遊してもコンバージョン地点に着かない。**

### ★ 弱点C｜**この記事の型は、AI Overviews に最も食われやすい**

`検証済み`（出典の記述）— [株式会社JADE のブログ（2026-04-30）](https://blog.ja.dev/entry/blog/2026/04/30/traffic-decline-not-always-ai)：

> AI Overview …ユーザーが知りたいことへの答えを検索結果ページ上で提供してしまうため、
> わざわざリンクをクリックしてサイトに訪問する必要がなくなります。…
> **特に「○○とは？」「○○の方法」といった情報収集型の検索で表示されやすい傾向があります。**

**このサイトの記事は「クーラーボックスに500mlは何本入る？」という、
答えが数値ひとつで完結する情報収集型のど真ん中。** AIOが最も要約しやすい形をしている。

⚠️ **同じ記事はAIOに「引用される側」にもなりうるので、悪いことだけではない。**
ただし**クリックされずに答えだけ持っていかれる形**であることは意識しておく必要がある。

⚠️ JADE の記事は同時に、**流入減をAIのせいと決めつけるなとも書いている。**
切り分けの指標は「**順位は変わっていないのに、クリック数だけが落ちているか**」。
→ **Search Console でこの形を見るまでは、AIOの影響と断定しない。**

`未検証` — 「AIOで自然検索のクリック率6割減」等の数字が各所に出回っているが、
**Google は公式に開示していない**（JADE も同様に指摘）。**このサイトの数字として採用しない。**

### ★ 弱点D｜**単価が構造的に足りない。しかも最新記事が最安ジャンル**

`検証済み`（`affiliate-program-facts.md` の実地確認）

```
クーラーボックス（スポーツ＆アウトドア 4%・6,000円）→ 240円/件
カセットコンロ（家電 2%・6,000円）           → 120円/件  ← 15ジャンル中 最下位
```

⚠️ **記事07で選んだカセットコンロは、調べた15ジャンルの中でいちばん報酬が低い。**
SERPの勝ち目と一次情報の有無だけで選び、**単価を見ていなかった。** これは選定の抜け。

試算（`serp-check.md` の仮定：リンククリック率20%・購入率5%）：

| ケース | 1件 | 1セッション | 月1万円に必要なセッション |
|---|---|---|---|
| Amazon クーラーボックス（現状） | 240円 | 2.40円 | **4,167** |
| Amazon カセットコンロ | 120円 | 1.20円 | **8,333** |
| Amazon スーツケース | 960円 | 9.60円 | 1,042 |
| Amazon＋楽天を併記（取りこぼし1.3倍と仮定・**未検証**） | 240円 | 3.12円 | 3,205 |
| ASP案件（1件2,000円・購入率2%と仮定・**未検証**） | 2,000円 | 8.00円 | 1,250 |

**ロングテール1記事が1位で250セッション/月**（`serp-check.md`）として：

```
月1万円  → 約17記事が1位
月3万円  → 約50記事が1位
月10万円 → 約167記事が1位
```

**Amazon単体・低単価ジャンルのままだと、記事数で殴るしかない構造。**

## 3. 外部調査（出典つき）

### 3-1. もしもアフィリエイト経由という選択肢

`検証済み` 出典：[もしもアフィリエイト公式](https://af.moshimo.com/) のトップページ本文

| 事実（公式の記述） | 意味 |
|---|---|
| **W報酬制度：通常報酬＋12%のボーナス報酬** | 同じ成果で1.12倍 |
| **「かんたんリンク」でAmazon・楽天の広告リンクを簡単に作れる** | **1つのリンクでAmazonと楽天を並べられる**＝楽天ユーザーの取りこぼしを拾える |
| **報酬1,000円以上で振込手数料0円** | 少額でも現金化できる |

`未検証` — 二次情報では「もしも経由のAmazonは公式より料率が低い（2023-02改定）」
「Amazon単体の180日3件のノルマなしで参入できる」という記述が複数ある
（[live-and-life.com](https://live-and-life.com/moshimo-amazon-rate/)／
[bloganswer.jp](https://bloganswer.jp/amazon-affiliate-moshimo/)）。
**もしも公式の料率ページで確認していない。採用前に必ず一次情報を取ること。**

### 3-2. 楽天アフィリエイトの上限

通常は**商品ジャンル別2〜4%で、1商品1個あたり1,000円の報酬上限**があるが、
ショップが料率アップを設定した商品は上限の対象外になる。
出典：[楽天アフィリエイト 料率アップ一覧（公式）](https://affiliate.rakuten.co.jp/recommend/uplist/)／

- ⚠️ **クッキーは24時間**（カート投入なら89日）→ 結論を記事後半に置くと取りこぼす

## 4. 打ち手（優先順）

### 優先1｜**測定を始める**（構成の話より先）

1. **アソシエイトに申請し、リンクを実装して `affiliateEnabled: true` にする**
   → `build.mjs` の `resolveLinks()` が意図的に例外を投げるので、実リンク解決の実装が要る
2. 測るのは2つだけ：**記事→Amazonのクリック率**と、**クリック→購入率**
   - 分母（セッション）は Cloudflare Web Analytics（導入済み）
   - 分子（クリック・注文）はアソシエイト・セントラルのレポート
3. **`serp-check.md` の収益モデルを実測値で置き換える**

⚠️ **180日タイマーが動く。** 申請の可否は利用者の判断（第6節）。

### 優先2｜**収益記事を1本作り、既存7本から内部リンクを集める**

いまの7本は全部「答え」で終わっている。その先の受け皿を作る。

```
集客記事（既存7本）              収益記事（新規1本）
  500mlは何本入る？          →   「用途別・クーラーボックスの選び方と比較」
  2Lは立つ？                 →     ・500ml中心なら → この内寸
  保冷剤で何本減る？          →     ・2Lを立てたいなら → 深さ310mm以上
  容量Lの正体                →     ・釣りで大物なら → 内寸の長辺
  ダイワ vs シマノ            →     ・軽さ優先なら → 自重
  内寸の長さ                 →   ここに商品リンクを集約する
```

**このサイトは既に比較の材料（内寸・外寸・自重・KEEP/COOL）を全部持っている。**
足りないのは**それを「選び方」として1枚にまとめたページ**だけ。

### 優先3｜**リンクをAmazon単独から「Amazon＋楽天」に変える**

もしもの「かんたんリンク」を使うと1つのブロックで両方出せる（第3-1節）。
**同じセッションから拾える確率が上がる。**
⚠️ 料率が公式Amazonより低い可能性があるので、**一次情報で確認してから決める。**

### 優先4｜**次に書くジャンルは「単価 × 勝ち目」で選ぶ**

記事07の反省。`affiliate-program-facts.md` の結論をもう一度使う：

> **正しい判断軸は「単価 × 料率」の一本。料率表だけを見て絞ると間違える。**

これに `serp-check.md` の勝ち目判定を掛ける。**両方見る。**

### 優先5｜**記事の型に「だから何を買うか」を足す**（AIO対策）

数値の答えだけの記事はAIOで完結されやすい（第2節C）。
**答え＋選択の指針**まで書くと、要約されにくく、収益記事への導線にもなる。

## 5. やらないと決めること

- **煽り文句（数量限定・在庫僅少）** — 景表法リスク。`affiliate-program-facts.md` で既に不採用と決めている
- **価格の手打ち** — Amazon規約違反。PA-APIが使えるまで不可
- **記事数だけを増やす** — 測定が動くまでは、増やしても検証にならない
