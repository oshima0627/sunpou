### なぜこの塊がこのサイトに向いているか

`docs/serp-check.md` が実データから導いた「勝てる型」は2つだけだった。
**土鍋の号数は、その両方に当てはまる。**

| 勝てる型 | 土鍋 号数がなぜ当てはまるか |
|---|---|
| **メーカーをまたぐ横断比較** | 号数（尺貫法の寸）と実際の直径・容量の対応は**メーカーごとにばらける**。1社の公式ページでは「9号＝何cm・何L・何人前」の横断表は作れない |
| **カタログに載っていない数値** | 通販の商品ページは「9号」としか書かないことが多い。**内径・満水容量・実容量を並べたものが無い** |

⚠️ **一方で「土鍋 24cm 何号」のような単位換算そのものは、まとめ記事が既に大量にある。**
勝てるとすれば **「メーカー公表値を並べて、号数が実寸をどれだけ決めていないかを示す」** 側。
`/cassette-konro/donabe-nangou/`（「9号まで」は号数だけでは決まりません）と**同じ切り口**で、
すでに1本その形で書けている。

### 収益の側から見ても向いている

- 土鍋は **単価3,000〜10,000円台の指名買い**。「何号を買えばいいか」が決まれば、そのまま買う
- 審査に要るのは **販売3件**であって金額ではない。**冬に売れる安い定番品**が最短距離
- カセットコンロ・カセットボンベ・土鍋は**同じ食卓で一緒に買われる**。既存4記事と束にできる


検索リンクは `build.mjs:61-69` に**意図した設計**として理由が書いてある
（ASIN は別物を指す事故を起こす／検索なら常に現行品を指す）。規約上も条件つきで認められている。

**ただし収益の観点では、これは1クリック分の余計な段差を全リンクに入れている。**
押した人は検索結果ページに着き、そこで**もう一度自分で選ぶ**。

**→ 今回は直していない。** 理由は測れないから：

- クリック総数が **4件**。うち外部由来と確認できたものは **0件**
- ここを変えても、変えた効果を**何と比べればいいのかが存在しない**
- 先に流入が立ち上がってからでないと、良くなったのか季節なのか区別がつかない

⚠️ **ただし「やらない」ではなく「順番が後」。** 流入が立ち上がったら、
まず**製品カード30枚だけ**を直リンクに変えて A/B ではなく前後で比べるのが最小の手。
`build.mjs` の `[[LINK:]]` に ASIN を渡せる形（`[[LINK:商品名|ASIN]]`）を足せば
記事の書き方は変えずに済む。**ASIN は1件ずつ実際に開いて確かめること。**

## D. **更新日が事実と違っていた**　`検証済み` → 直した

`git log` と front matter を突き合わせたら、**20本中18本がずれていた。**

```
git の最終コミット日   front matter の updated:
2026-09-01             2026-08-24    coolerbox-500ml-honsuu.md
2026-09-01             2026-08-25    kyatatsu-secchi.md
...（18本）
```

同日午前の修正（**「26製品」→「33製品」の事実修正**を含む）で19記事を書き換えたのに、
`updated:` を上げていなかった。その結果、次の3つが**同時に**古いままだった。

| どこ | 何が古かったか |
|---|---|
| `sitemap.xml` の `lastmod` | 直した記事が「8/24 から変わっていない」と申告していた＝**再クロールの合図が出ていない** |
| JSON-LD の `dateModified` | 同上 |
| 記事に表示される「更新 …」 | **事実を直した日を読者に出していない** |

⚠️ **一次情報から計算することを売りにしているサイトで、直した日を出さないのはまずい。**

→ 直し方は下の「対処」に書いた。**手で書くとまた忘れるので git から引くようにした。**
