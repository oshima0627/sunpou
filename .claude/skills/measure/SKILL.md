手順の原型は `docs/measurement-2026-08-31.md`。**前回の測定ファイルを先に読むこと**（差分で書くため）。

## 前提

- Chrome が繋がっていること（`mcp__claude-in-chrome__*`）。利用者のログイン済みセッションを使う
- 前回の `docs/measurement-*.md` を読んでいること

## 手順

### 1. Search Console：全体の数字

`https://search.google.com/search-console/performance/search-analytics?resource_id=sc-domain%3Asunpou.nexeed-lab.com&metrics=CLICKS%2CIMPRESSIONS%2CPOSITION`

表示回数・クリック数・平均CTR・平均掲載順位・**データの最終日**を控える。

⚠️ **GSC のデータは2〜3日遅れている。** 「今日の数字」ではない。**必ず最終日を記録する。**
⚠️ **前回と最終日が同じなら、それ以上読んでも新しい情報はない。** そこで止める。

### 2. ページ別・クエリ別

URL に `&breakdown=page` を足すとページ別。クエリ別はタブを切り替える。

⚠️ **表示回数が少ないうちはクエリが匿名化されて見えない。** 「見えない」ことを記録する
（2026-08-31 は30表示のうち28件が非表示だった）。

### 3. インデックス

- サイトマップ：`/search-console/sitemaps?resource_id=...` で最終読み込みと検出ページ数
- 個別：上部の検査ボックスに URL を入れる

⚠️ **同じURLにインデックス登録を再送信しない。** 順番も優先順位も変わらない（ダイアログ原文）。

### 4. アソシエイト・セントラル

`https://affiliate.amazon.co.jp/home` でクリック数・注文・紹介料・データ最終更新日。

⚠️ **クリック数を CTR の分子に使わない。** Cloudflare の訪問は direct ばかりで、
自分の確認アクセスと切り分けられない。

### 5. 記録する

`docs/measurement-YYYY-MM-DD.md` に書く。**前回との差分表を必ず入れる。**

⚠️ **標本が小さいうちはクリック0からCTRを判定しない。**
先に**期待クリック数**と**0回になる確率**を出す（ポアソン `P(0)=e^-λ`）。
例：11表示・7.4位でCTRを10%と仮定しても期待1.1回、0回になる確率は33%。**判定できない。**

⚠️ **仮定した数値には `未検証` と明記する。** CTRの一般値も、購入率の仮定も一次情報ではない。

### 6. HANDOFF.md を書き直す

**継ぎ足さない。古くなった記述を消して書き直す。** 履歴は git log にある。

## 完了条件

- `docs/measurement-YYYY-MM-DD.md` があり、**前回との差分表**と**データの最終日**が書かれている
- `HANDOFF.md` の該当節が書き直されている
- 見立てが前回と変わったなら、**どこが外れていたかを明記している**

## 失敗したとき

| 起きたこと | 対処 |
|---|---|
| GSC の最終日が前回と同じ | **新しい数字はない。** そう報告して終わる。無理に読み込まない |
| 「データを処理しています」 | そのレポートは諦め、URL検査で個別に見る。**処理待ちであることを記録する** |
| ログインを求められた | **認証情報を扱わない。** 利用者にログインを依頼して止まる |
